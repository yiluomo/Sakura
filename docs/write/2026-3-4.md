# 更新日志

## 2026-03-04 - 长期记忆重构 & 桌面化

### 新增功能

1. **长期记忆文件化存储**
   - 长期记忆不再只存 MySQL，同时写入 `Sakura/memory_store/*.md` 文件
   - 按语义分4个文件：`profile.md`（档案）、`preferences.md`（偏好）、`notes.md`（笔记）、`summaries.md`（对话摘要）
   - 文件人类可读，可直接打开编辑；每条记忆用 `<!-- entry: type/key -->` 注释标记，程序据此定位更新

2. **LLM 自动提取记忆关键词**
   - 保存记忆时调用 LLM 提取 5~10 个检索关键词
   - 关键词存入数据库 `keywords` 字段，同步写入 `.md` 文件
   - 提取失败时静默降级，不阻断保存流程

3. **手动归档记忆按钮**
   - 前端顶部新增"归档记忆"按钮（替换原"清空对话"按钮）
   - 点击后弹出确认框，调用 LLM 总结当前全部短期记忆后写入 `summaries.md`
   - 归档成功后自动清空前端对话列表和数据库短期记忆记录

4. **Electron 桌面应用**
   - 前端支持以桌面窗口方式运行（不需要浏览器）
   - 开发模式：`npm run electron:dev`（热重载）
   - 打包模式：`npm run electron:build`（生成 Windows 安装包 `.exe`）

5. **对话摘要分卷存储**
   - 摘要文件从单一 `summaries.md` 改为按数量分卷：`summaries_1.md`、`summaries_2.md`……
   - 每卷最多存储 **10 条**摘要，满后自动新建下一卷（`SUMMARIES_MAX_ENTRIES = 10`）
   - 写入路由规则：已存在 key → 原卷原地更新；新 key → 最新未满卷；全满 → 新建下一卷
   - `write_entry()` 返回值由 `None` 改为 `str`（实际写入的文件相对路径），调用方直接使用该值写数据库 `file_path` 字段


### 数据库变更

`long_term_memory` 表结构调整（**需重新执行 `migrate_db.py`**）：

| 字段 | 变更 |
|------|------|
| `user_id` | ❌ 已移除（单用户系统无需此字段） |
| `keywords` | ✅ 新增（VARCHAR 500，LLM 提取的关键词，逗号分隔） |
| `file_path` | ✅ 新增（VARCHAR 200，对应 `.md` 文件路径） |
| `value` | 保留，改为只存前100字摘要 |

### 技术实现

#### 后端新增 / 修改

1. **`memory/keyword_extractor.py`**（新增）
   - `extract_keywords(content)` — 调用 LLM 提取关键词列表
   - `keywords_to_str(keywords)` — 列表转逗号字符串

2. **`memory/file_store.py`**（新增）
   - `write_entry()` — 写入 / 更新 `.md` 文件中的记忆条目
   - `get_top_memories()` — 读取文件，按重要度排序，格式化注入 prompt
   - `get_relative_path()` — 根据 `memory_type` 返回目标文件的相对路径
   - 全局写锁（`asyncio.Lock`）保障并发安全

3. **`memory/long_term.py`**（重构）
   - `confirm_save_memory()` — 三步写入：LLM 提取关键词 → 写文件 → 写数据库索引
   - `get_profile()` — 改为从 `.md` 文件读取，不再查数据库

4. **`memory/short_term.py`**（修改）
   - `compress_and_archive()` — 自动压缩归档同步更新为双轨写入（文件+数据库）
   - `force_archive()`（新增）— 无视阈值，手动归档全部短期记忆

5. **`api/chat.py`**（修改）
   - 新增 `POST /api/memory/archive` — 手动归档接口

6. **`db/crud.py`**（修改）
   - 移除旧函数的 `user_id` 参数
   - 新增 `save_or_update_long_term_memory()` 统一写入入口

7. **`db/models.py`**（修改）
   - `LongTermMemory` 新增 `keywords`、`file_path` 字段，移除 `user_id`

8. **`config.py`**（修改）
   - 新增 `SAKURA_ROOT`、`MEMORY_STORE_DIR` 路径常量
   - 支持环境变量覆盖 `DATABASE_URL` 和 `MEMORY_STORE_DIR`（Docker 用）

9. **`migrate_db.py`**（重写）
   - 安全迁移：先读旧数据写入 `.md` 文件，再重建表结构

#### 前端新增 / 修改

1. **`electron/main.js`**（新增）
   - Electron 主进程，创建 1100×780 桌面窗口
   - 开发模式加载 `http://localhost:3000`，生产模式加载 `dist/index.html`

2. **`package.json`**（修改）
   - 新增：`"main": "electron/main.js"`
   - 新增脚本：`electron:dev`（并发启动 Vite + Electron）、`electron:build`（打包 exe）
   - 新增 devDependencies：`electron`、`electron-builder`、`concurrently`、`wait-on`、`cross-env`

3. **`vite.config.ts`**（修改）
   - `base` 在 Electron 打包模式下改为 `./`（相对路径）
   - `server.open` 改为 `false`（Electron 模式下不自动打开浏览器）

4. **`src/views/ChatView.vue`**（修改）
   - "清空对话"按钮 → "归档记忆"按钮（调用 `/api/memory/archive`）
   - 归档成功后自动清空消息列表

5. **`src/api/chat.ts`**（修改）
   - 新增 `archiveMemory()` API 方法
