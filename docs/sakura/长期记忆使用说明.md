# 长期记忆功能使用说明

## 功能概述

长期记忆系统支持智能关键词检测和分类保存。当用户输入"记住"开头的消息时：
1. **八重樱会正常回复**（不受影响）
2. **同时弹窗确认**是否保存为长期记忆
3. **记忆保存是后台操作**，不会打断对话流程
4. **LLM 自动提取关键词**（5~10个），便于日后检索
5. **记忆同时写入文件和数据库**，文件供人类查看，数据库用于快速索引

## 使用方式

### 1. 基本语法

```
记住 + 内容
```

### 2. 支持的记忆类型

系统会自动检测以下关键词并分类保存：

| 记忆类型 | 关键词 | 重要度 | 存储文件 | 示例 |
|---------|--------|--------|---------|------|
| 姓名 (name) | 我叫、我的名字、叫我、我是 | 5 | profile.md | "记住我叫依洛沐" |
| 爱好 (hobby) | 我喜欢、我爱、我的爱好、我喜爱 | 4 | preferences.md | "记住我喜欢看书" |
| 厌恶 (dislike) | 我讨厌、我不喜欢、我厌恶 | 4 | preferences.md | "记住我不喜欢辣的" |
| 家人 (family) | 我的家人、我的父母、我的爸爸、我的妈妈 | 5 | profile.md | "记住我的妈妈是老师" |
| 朋友 (friend) | 我的朋友、我的好友 | 4 | profile.md | "记住我的朋友叫小明" |
| 生日 (birthday) | 我的生日、我生日、我出生 | 5 | profile.md | "记住我的生日是3月15日" |
| 年龄 (age) | 我今年、我的年龄、我多大 | 4 | profile.md | "记住我今年25岁" |
| 居住地 (location) | 我住在、我来自、我在、我的家乡 | 4 | profile.md | "记住我住在北京" |
| 职业 (occupation) | 我的工作、我是、我做、我的职业 | 4 | profile.md | "记住我的工作是程序员" |
| 经历 (experience) | 我曾经、我以前、我经历过 | 3 | preferences.md | "记住我曾经去过日本" |
| 通用 (manual) | 无关键词时 | 3 | notes.md | "记住今天天气很好" |

### 3. 使用示例

#### 示例1：保存新记忆

**用户输入：**
```
记住我叫依洛沐
```

**系统响应：**
1. **八重樱正常回复**（例如："好的，依洛沐。"）
2. **同时弹出确认对话框**：
   ```
   标题：保存记忆
   内容：检测到【姓名】信息，是否保存？
         内容：我叫依洛沐
   按钮：[保存] [取消]
   ```

**用户点击"保存"后：**
- LLM 自动提取关键词：`依洛沐、姓名、名字、用户、称呼`
- 写入 `memory_store/profile.md`，格式如下：
  ```markdown
  ## 姓名
  **内容**：我叫依洛沐
  **关键词**：`依洛沐` `姓名` `名字` `用户` `称呼`
  **重要度**：5
  **更新时间**：2026-03-03 16:00
  ```
- 数据库索引同步写入（memory_type, key, keywords, file_path）
- 显示成功提示："记忆已保存"

#### 示例2：更新已存在的记忆

**用户输入：**
```
记住我叫伊洛沐
```

**系统响应：**
1. **八重樱正常回复**
2. **同时弹出确认对话框**：
   ```
   标题：更新记忆
   内容：检测到【姓名】信息，是否更新？
         旧值：我叫依洛沐
         新值：我叫伊洛沐
   按钮：[更新] [取消]
   ```

**用户点击"更新"后：**
- `profile.md` 中对应条目就地更新（不追加，覆盖旧内容）
- 数据库索引同步更新
- 显示成功提示："记忆已保存"

#### 示例3：取消保存

**用户点击"取消"后：**
- 显示提示："已取消保存"
- 八重樱的回复保持不变
- 不会浪费 LLM 关键词提取调用（关键词提取在确认后才执行）

### 4. 通用记忆

如果输入的内容不包含任何关键词，系统会将其保存为"通用记忆"（存入 `notes.md`）：

**用户输入：**
```
记住今天天气很好
```

**系统响应：**
1. **八重樱正常回复**
2. **同时弹出确认对话框**

## 核心特性

### 1. 不影响对话流程

- ✅ 八重樱始终正常回复，不会被记忆保存打断
- ✅ 记忆保存是后台操作，通过弹窗异步确认
- ✅ 用户可以边聊天边决定是否保存记忆

### 2. LLM 智能关键词提取

- 每次保存时调用 LLM 提取 **5~10 个**检索关键词
- 关键词聚焦实体、概念、事件，便于日后精准检索
- 提取失败时静默降级（关键词留空），不阻断保存流程

### 3. 双轨存储：文件 + 数据库

| 存储位置 | 内容 | 用途 |
|---------|------|------|
| `memory_store/*.md` | 完整记忆内容（Markdown） | 注入 prompt、人工查看/编辑 |
| `long_term_memory` 表 | 轻量索引（keywords + file_path） | 去重检查、快速检索 |

### 4. 人类可读的记忆文件

记忆按语义分4个文件存储，可以直接打开查看和编辑：

```
Sakura/memory_store/
├── profile.md       # 个人档案
├── preferences.md   # 偏好与经历
├── notes.md         # 手动笔记
└── summaries.md     # 对话摘要（自动生成）
```

### 5. 去重机制

- 检测是否已存在相同类型的记忆（按 memory_type + key）
- 如果存在，提示用户是否更新
- 显示旧值和新值对比

### 6. 自动对话摘要归档

当对话数量超过阈值（默认200条）时，系统自动：
1. 取出最早的150条对话
2. 用 LLM 总结关键信息
3. 提取关键词
4. 写入 `summaries.md` 和数据库索引
5. 删除已归档的原始对话记录

## 技术实现

### 后端流程

1. **正常对话**：`conversation.py` 调用LLM生成回复
2. **保存短期记忆**：将对话保存到数据库
3. **检查记忆触发**：`check_memory_trigger()` 检测"记住"关键词
4. **返回双重信息**：同时返回回复和记忆信息（`memory_info`）
5. **用户确认后**：
   - `keyword_extractor.py` 调用 LLM 提取关键词
   - `file_store.py` 写入对应 `.md` 文件
   - `db/crud.py` 写入数据库索引

### 前端流程

1. **发送消息**：用户输入"记住..."并发送
2. **显示回复**：立即显示八重樱的回复
3. **检查记忆信息**：如果有 `memory_info`，弹出确认对话框
4. **异步确认**：用户确认后调用 `/api/memory/confirm`
5. **显示结果**：显示保存成功或取消的提示

### 数据库存储

记忆索引保存在 `long_term_memory` 表中：

```sql
CREATE TABLE long_term_memory (
    id          INT PRIMARY KEY AUTO_INCREMENT,
    memory_type VARCHAR(50),   -- 记忆类型（name, hobby, manual 等）
    key         VARCHAR(100),  -- 触发关键词（"我叫"、"我喜欢"等）
    value       TEXT,          -- 内容摘要（前100字）
    keywords    VARCHAR(500),  -- LLM提取的关键词，逗号分隔
    file_path   VARCHAR(200),  -- 对应 .md 文件路径
    importance  INT,           -- 重要度（1-5）
    created_at  DATETIME,
    updated_at  DATETIME
);
```

## 注意事项

1. 必须以"记住"开头才会触发记忆保存检测
2. 关键词提取在用户**确认后**才执行，取消不会调用 LLM
3. 即使取消保存，对话仍会被记录在短期记忆中
4. 重要度越高的记忆在回忆时（注入 prompt）优先级越高（最多取前5条）
5. 同一类型的记忆会被去重，就地更新（文件中覆盖旧条目）
6. `memory_store/` 目录可以直接打开 `.md` 文件查看和手动编辑记忆
7. 使用 Docker 部署时，`memory_store/` 内容保存在 Docker Volume 中，需单独备份
